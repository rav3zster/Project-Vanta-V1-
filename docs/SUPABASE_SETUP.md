# PROJECT V1 — Supabase Setup

This build runs on the **Figma Make** stack: a Vite + React frontend, a **Supabase
Edge Function** backend (Hono/Deno), and **Supabase Auth**. Persistence uses the
Make-provided `kv_store` table (real Postgres, JSONB values), not hand-written SQL
migrations. Authorization is enforced **server-side in the edge function** (see
`supabase/functions/server/rbac.tsx`) rather than through RLS policies, because the
KV store is a single table. The tournament lifecycle is nonetheless real and
persisted.

## What is automatic
- Supabase connection + keys — wired by Make (`utils/supabase/info.tsx`, autogenerated).
- The `kv_store_d346d9b8` table — created by Make.
- Auth users + profiles + the 8-team tournament — created by the **Seed** action.

## What you must do
1. **Deploy the edge function.** After any change under `supabase/functions/server/`,
   redeploy it from the **Make settings page** (Supabase → Deploy edge function).
   Nothing server-side works until this is deployed.
2. **Rotate your secret key.** The `sb_secret_...` key was pasted in chat — roll it in
   Supabase → API Keys. The publishable/anon key is safe to expose.
3. **Seed + run the lifecycle:**
   - Open the app → **LOG IN** → create an account (that account is a `HUMAN`), or use a
     dev account after seeding.
   - To seed, you need a privileged account. Sign up once, then in Supabase → Table
     editor → `kv_store_d346d9b8`, find your `user:<id>` row and set `"role": "GOD"`.
     (One-time bootstrap so no signup form can mint an admin.)
   - Log in as that GOD account → **CONTROL** → **SEED 8-TEAM TOURNAMENT**. This also
     creates dev accounts:
     - `god@projectv1.dev` / `demigod@projectv1.dev` / `human@projectv1.dev`
     - password: `vanta-dev-2026` (development only)

## Running the lifecycle (CONTROL panel)
`ROSTER_LOCK → OPEN CHECK-IN → mark 8 teams in → CLOSE CHECK-IN → BEGIN SEEDING →
RANDOMIZE SEEDS → LOCK SEEDING → GENERATE BRACKET → GO LIVE → finalize each match
(or forfeit / dispute → resolve) → CHAMPION`.

Every mutation is permission-checked and written to the append-only **audit log**
(visible in CONTROL for `audit.view` holders). The public homepage's featured
tournament reads this same live state.

## Roles & permissions
`GOD` (all), `DEMI_GOD` (operations, no admin/role management), `HUMAN`
(submit results, open disputes). Defined in `supabase/functions/server/rbac.tsx`.

## Honest limitations
- Not Next.js/App Router; no SSR, per-route URLs, or SEO metadata pipeline.
- Persistence is KV, not a normalized relational schema; authorization is
  server-enforced, not RLS. The full multi-table schema in the brief is not created.
- Discord, payments/compliance, storage/evidence uploads, notifications delivery,
  and automated tests are not implemented — the lifecycle vertical slice is.
